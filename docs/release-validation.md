# PageInk 0.1.1 发布验证

此页保留 0.1.1 初始发布构建的验证记录。后续工作区改版的构建哈希与实际结果见 [工作区改版](workspace-redesign.md)。

正式名称：页墨手记 PageInk；插件 ID：`pageink`。自有代码采用 MIT，第三方代码及字体保留原许可。当前界面为简体中文。

本版将原开发版的外部字体、PDF Worker、CMap 与解码资源内嵌到 `main.js`，适配社区目录只安装 `main.js`、`manifest.json`、`styles.css` 的行为。资源在本地按需读取，不从网络下载、不运行自更新或自安装。

## 实际执行

验证环境为 Windows Obsidian 1.12.7；主脚本 SHA-256：`7e68f688e959743d513439989a344e25f8a37226695569ddb0664b52269072ba`。

- 构建、TypeScript 检查与 28 项单元测试通过。新增检查覆盖 Worker 转移 ArrayBuffer 后资源仍可重读，以及 Blob URL 复用、卸载释放和再次创建。
- 全新隔离库仅安装三个主文件，首次启用前屏蔽全部 HTTP/HTTPS。启用耗时约 1.23 秒；这是该 Windows 宿主的一次样本，不是跨设备性能保证。
- 从旧开发版完整打包恢复三页文档，中文正文、草稿图片和来源关联正常。编辑、保存、关闭重开及中文 PDF Worker 导出、重新导入渲染通过。
- 三轮插件卸载/重载：每次卸载后，本插件创建的 Blob URL 为 0，字体数量恢复到宿主基线 7；重载后文档可读。
- CropBox、0/90/180/270 度旋转、透明度与标准字体的四页 PDF 导出重开，逐像素平均误差为 0。
- 常规 JPEG 2000 样本 `perf_codecs_jpx.pdf`、混合 CMap 文本样本 `perf_text_cmap_mixed.pdf`，与未修改的 PDF.js 5.4.624 原始文件资源路径对照，逐像素误差为 0，未出现解码警告。样本来源为 Mozilla 的 [PDF.js 测试集](https://github.com/mozilla/pdf.js/tree/master/test/pdfs)，不随插件分发。
- 上述三文件核心流程页面错误与外部网络请求均为 0。

## 未通过的实验及限制

- 第一次新库启用被 Obsidian 自带的“是否信任此库作者”界面阻止，尚未执行插件。信任本次生成的测试库后重新运行，以上流程才通过；初次记录不计为通过。
- 对照脚本起初给原版 PDF.js 创建了不同的 Canvas 上下文，造成文本抗锯齿差异；统一为相同 2D 上下文后，常规 JPX 和 CMap 文本逐像素一致。
- 上游当前测试集中的 `jpx_subsampling.pdf`、`bug_jpx.pdf`、`jpx_numcomps.pdf` 触发部分 JPX 解码警告；未修改的 PDF.js 对照路径也有失败，其中两个样本仍有像素差异。不能将这些特殊 JPX 样本记为通过，不能据此承诺所有 JPEG 2000 编码变体均正确显示。导出分享前请检查原 PDF 的图片是否完整。
- 重载测试的自然 JS 堆读数从约 0.53 GB 上升到 0.93 GB。随后包含额外 PDF.js 对照模块的显式 GC 诊断在暖机后约 1.03 GB 趋于稳定；这是诊断堆数据，不能当作常规使用或进程内存峰值，也不足以证明所有内存问题已解决。
- `main.js` 约 46 MB，完整资源离线分发有下载、解析与解压成本。
- 没有 iPad、Apple Pencil 真机或实际同步服务验证。合成输入与桌面模拟视口不能替代这些证据。iPad 的掌触、软键盘、转屏、物理笔感与内存边界仍需真机确认。
- 本次未在新主脚本上重复 60/120 分钟长测。旧开发版 `bb002975…` 的完整长测、磁盘重开和历史中断证据保留在本地；它们不属于本版的新长测结果。极大画布全览仍有明显耗时和内存成本，不能宣称所有场景均达到 60 FPS。

首版功能范围保持不变；公开早期版本不等于完整双平台验收。市场收录状态以 Obsidian Community 的实际结果为准。
