# 原生文字工作区

这是笔记本与无限画板一体化的第一阶段：统一进入文档的方式，接入真实 Markdown 编辑与手写区域引用。文字正文保存在普通 `.md`，由 Obsidian 原生 `MarkdownView` 负责编辑与保存；现有 `.inknote`、笔迹资源、稳定区域 ID 和完整可编辑备份保持兼容。

## 已实现的流程

- 从 PageInk 笔记库新建文字、手写笔记本或自由画布，打开库内 Markdown、手写文档和 PDF。
- 按类型筛选，以名称和路径搜索；按最近修改排序。每次显示 60 项，继续显示后续项。损坏的手写入口仍列出，并显示读取问题。
- 原生文字视图提供「笔记库」「插入笔记链接」「插入手写区域」和阅读／编辑切换。工具栏只增添一个独立容器，保留原生视图类型、编辑器、属性、文件菜单和宿主命令。
- 插入区域时先选择手写文档，再选择书签。内容是原生文件链接加现有 `drawing-region` 代码块；文件链接由 Obsidian 解析，区域使用文档与书签 ID 定位。
- 打开已加载的文档时复用它的标签页；其他文档在新标签中打开，笔记库保留筛选状态。

区域插入通过原生 `Editor.replaceRange` 完成一次编辑，保存由 `MarkdownView.save()` 负责。异步选择期间若文件、模式或正文已变化，会停止插入并提示重新选择，避免向旧位置或另一份文档写入。不会通过 `Vault.modify` 与正在使用的编辑器争写正文。

## 源码职责

| 文件 | 职责 |
| --- | --- |
| `src/notes-host.tsx` | Obsidian 适配：笔记库视图、原生文字工具栏、文件打开、引用选择与原生编辑器写入。宿主事件及组件在卸载时清理。 |
| `src/Library.tsx` | 不引用 Obsidian API 的笔记库界面，包含加载、筛选、列表分页和错误反馈。 |
| `src/notes.ts` | 文档条目、筛选、稳定区域引用序列化及 Markdown 块插入边界。 |
| `src/main.tsx` | 注册适配服务；新建真实 `.md`；接入既有手写保存与区域预览。 |
| `src/host.ts` | 向手写工作区提供笔记库导航。 |

宿主集成使用公开 API，不构造内部编辑器，不替换全局 `.md` 文件处理器，不修改 Canvas 的原型。文字工具栏在插件启用期间附加到已加载的原生 Markdown 视图，禁用时移除；原生视图本身继续工作。

笔记库缓存轻量的手写文档摘要，不缓存第二份 Markdown 正文；每批最多读取 12 个入口，文件变化触发刷新。`InkCanvas.tsx`、笔迹采样、内核补丁和跨页／草稿历史仍遵循 [内核边界](kernel-patches.md)。

## 当前边界

- 第一阶段通过区域引用联通文字与手写。第二阶段已增加普通文字段落投影、同页手写和段落级笔迹锚定，见 [混合笔记本](mixed-notebooks.md)。第三阶段已支持画板文字卡片的段落原位编辑及手写区域卡片，见 [画板内容卡片](board-cards.md)；卡片内富文本排版与直接手写仍未实现。
- Obsidian 原生历史可能包含不改变正文的记录，撤销正文前可能先经历这样的步骤。PageInk 保留宿主的默认快捷键与历史；验证要求首个改变正文的撤销完整移除引用，重做原样恢复，并单独记录无正文变化的步骤数量。
- 原生文件链接的改名维护遵循 Obsidian 的自动更新链接设置。代码块中的路径可以保留旧值，区域读取按稳定文档 ID 查找；这不代表代码块内自定义引用已经进入原生反向链接索引。
- 第四阶段已在笔记库加入跨笔记正文／属性搜索、今日记录和属性编辑；范围与限制见 [统一笔记库](unified-library.md)。手写尚无 OCR。
- `.inkpack` 已随第二阶段纳入文字段落投影的原文快照；它不自动收集其他外部 Markdown。包含区域引用的独立 `.md` 与手写来源仍需要一并备份。
- 第三方插件、任意主题、中文输入法组合输入、iPad/Pencil 和实际同步服务需要各自验证；不能从桌面文字输入或鼠标绘制结果推断。

## 验证方式

```bash
npm run typecheck
npm test
npm run build
node dev/notes-workflows.mjs
node dev/workflows.mjs
```

两份宿主脚本只使用 `dev/obsidian.mjs` 生成的 `.test-vault/` 与临时配置，依次执行，不同时争用测试库或热更新运行中的构建。截图与报告保存在忽略的 `artifacts/`；`notes-validation.json` 记录新增流程、环境和构建 SHA-256，`workflow-validation.json` 记录现有手写、PDF 和导出的回归结果。
